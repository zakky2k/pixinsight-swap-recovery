# PixInsight Parallel Swap → XISF Recovery

A standalone Python utility to reconstruct image pixel data from **orphaned PixInsight parallel `.swp` files** and save them as **XISF 1.0** images. No additional Python packages are needed.

> [!WARNING]
> This project reverse-engineers an **undocumented** PixInsight swap layout. It is not affiliated with or endorsed by Pleiades Astrophoto / PixInsight. It is a best-effort recovery tool, not a substitute for saving images or projects. **Work on a copy of an inactive swap directory** and visually inspect recovered results in PixInsight before trusting or deleting source data.

## What it can recover

| Input pixel type | Channels | XISF output | Reconstruction method |
|---|---:|---|---|
| 32-bit floating point (`Float32`) | 1 (Gray) | `Float32 Gray` | Concatenates segment pixel blocks |
| 32-bit floating point (`Float32`) | 3 (RGB) | `Float32 RGB` | Reorders per-segment RGB channel blocks into planar channels |
| 16-bit unsigned integer (`UInt16`) | 1 (Gray) | `UInt16 Gray` | Concatenates segment pixel blocks |
| 16-bit unsigned integer (`UInt16`) | 3 (RGB) | `UInt16 RGB` | Reorders per-segment RGB channel blocks into planar channels |

This is **not** a TIFF, FITS, or PixInsight project-file recovery utility. It reconstructs image pixel arrays. Processing history, STF settings, FITS keywords, WCS, masks, and other original metadata are outside its recovery scope.

**Known compatibility:** The original recovery scenario used 14-way parallel `.swp` files on Windows. The owner reports **50 of 50 candidate images recovered** with the pre-release implementation and confirmed that recovered output opened in PixInsight. For the 1.0.0 release candidate, a fresh batch recovered the same 50 images with matching SHA-256 hashes of their pixel attachments. All 50 also passed structural checks. Other PixInsight versions and swap configurations may differ. The test suite checks synthetic samples of the known binary layout; it does not certify every possible swap variant.

## Requirements

- Python 3.9+ (standard library only)
- Sufficient free space for **uncompressed** XISF output (often hundreds of MB or several GB per image)
- A backup copy of the swap directory, not being modified by PixInsight

## Getting started (PowerShell)

Download or clone the repository and open PowerShell in its root folder.

**Preview recoverable images without creating files:**

```powershell
python .\pi_swap_to_xisf.py --all "swap_backup" --output-dir "recovered" --dry-run
```

**Recover the entire directory:**

```powershell
python .\pi_swap_to_xisf.py --all "swap_backup" --output-dir "recovered"
```

**Recover a single image:** supply the primary file (not `-part001.swp`):

```powershell
python .\pi_swap_to_xisf.py "swap_backup\~PI~TOKEN~ImageName.swp" "recovered\Recovered_ImageName.xisf"
```

The associated numbered `-partNNN.swp` files must be in the same directory as the primary file.

**Validate a recovered XISF's structural metadata and byte count:**

```powershell
python .\pi_swap_to_xisf.py --validate "recovered\Recovered_ImageName.xisf"
```

**Repair a header generated by an older version of this utility:**

```powershell
# IMPORTANT: Back up the XISF first; repair modifies the header in place.
python .\pi_swap_to_xisf.py --repair-header "recovered\Recovered_ImageName.xisf"
```

> `--repair-header` is for the particular fixed-offset XISF files produced by this recovery utility. **Do not run it on arbitrary XISF files** or on a file you haven't copied elsewhere.

## Viewing skipped and failed files in PowerShell

To see the filename above each skip or failure:

```powershell
python .\pi_swap_to_xisf.py --all "swap_backup" --output-dir "recovered" --dry-run |
    Select-String 'SKIP:|FAILED:' -Context 1,0
```

To preserve the complete output from a batch run:

```powershell
python .\pi_swap_to_xisf.py --all "swap_backup" --output-dir "recovered" |
    Tee-Object -FilePath .\recovery.log
```

Note: a repeat batch run does **not** overwrite output, but it may create additional files with unique suffixes. Use `--dry-run` when you only need a preview.

## How recovery works

1. Discover primary `*.swp` files, excluding numbered continuation files.
2. Verify the known `egamiwar` header signature, sample type, dimensions, channels, and parallel segment count.
3. Locate numbered segments and check their total byte count against expected pixel dimensions.
4. Reconstruct monochrome data in segment order; reconstruct RGB data by concatenating each segment's red block, then its green block, then its blue block.
5. Write an uncompressed XISF 1.0 file with the appropriate `sampleFormat`, `colorSpace`, and planar pixel storage.
6. Check the XISF preamble, XML structure and attachment size.

Recovery opens the original swap files in read-only mode. Batch conversion writes into a temporary subdirectory and publishes the verified file under its final `.xisf` name only after validation. On non-Windows systems, the output filesystem must support hard links. Existing filenames are disambiguated with the original swap-session token and, if needed, a number. If a file appears at the final path during recovery, that conversion fails without replacing the existing file.

## Limitations and safety

- Only the **two recognized signatures** (Float32 and UInt16) and **1/3 channels** are supported. Unknown formats are rejected rather than guessed.
- Structural validation checks expected header fields and byte lengths, **not image content or pixel continuity**. Inspect all important results in PixInsight, especially stars and channel registration.
- Images may be incomplete or contain work-in-progress data even when the swap files are perfectly consistent.
- The script expects segment-local RGB data to be separated into equal R/G/B blocks. Alternate PixInsight swap layouts may require different reconstruction logic.
- Does not recover PixInsight project state, windows, process histories, or metadata not contained in the swap pixel blocks.
- Avoid using active PixInsight swap directories. Recovered XISF outputs can be large.
- Use only on files you trust. As with any binary parser, malformed inputs may consume disk space or resources.

## Tests

```powershell
python -m unittest discover -s tests -v
```

Tests compare exact pixel bytes for all four format and channel combinations, including uneven RGB segment sizes. They also cover duplicate names, missing segments, malformed headers, and output overwrite protection. No original image data is included in this repository.

## Command-line reference

```powershell
python .\pi_swap_to_xisf.py --help
python .\pi_swap_to_xisf.py --version
```

Batch exit status is nonzero when a conversion fails; unsupported files are reported as **SKIP**, not failed. Review the summary carefully.

## Contributing

If your file is rejected, open an issue with your **PixInsight version, the error with filenames and paths removed, the image dimensions and sample type if known, and the segment sizes**. Keep source images, swap files, raw headers, and full logs private.

For consistency, any change to the pixel-layout algorithm should include a regression test. Please keep Float32 Gray/RGB and UInt16 Gray/RGB support intact.
